# DRAGON STUDIO — إعداد استقبال الطلبات آليًا (غير مُفعّل بعد)

هذه ملفات تجهيز فقط. الموقع المنشور حاليًا يرسل مسودة الطلب عبر واتساب أو يفتح رسالة بريد؛ لا توجد قاعدة بيانات متصلة حتى الآن.

## ما الذي سيحدث بعد التفعيل؟
عند الضغط على «إرسال طلب رسمي» في الموقع، سيُرسل نموذج المشروع إلى Google Apps Script من خلال POST، ويُسجّل صفًا في Google Sheets، ويُرسل إشعارًا إلى بريد DRAGON وبريد تأكيد للعميل. لا يُنشئ هذا حجزًا على Google Calendar؛ حجز Discovery Call يظل منفصلًا.

## الإعداد في حساب الشركة
1. سجّل الدخول إلى حساب Google الذي ترغب في إدارة بيانات العملاء عليه. يُفضّل بريد الشركة.
2. أنشئ Google Sheet جديدًا باسم DRAGON STUDIO — Client Leads.
3. افتح Extensions → Apps Script، والصق محتويات ملف Code.gs الموجود بجوار هذا الملف.
4. انسخ Sheet ID من عنوان الجدول وضعه مكان REPLACE_WITH_COMPANY_GOOGLE_SHEET_ID.
5. شغّل testSpreadsheetAccess وأكمِل أذونات Google المطلوبة.
6. اختر Deploy → New deployment → Web app. Execute as: Me. Who has access: Anyone.
7. انسخ رابط Web App المنتهي بـ /exec، وأرسل الرابط لنا لربطه بالموقع بعد تجربة طلب وهمي.
8. اختبر إدراج صف جديد ووصول رسالتين بريد. يجب التأكد من حصص MailApp ومن حماية عنوان Web App من الطلبات المزعجة.

## ملاحظات هامة
- أي نموذج منشور للعامة قد يتعرض للـspam، وفلتر الحقل الخفي غير كافٍ للأحجام الكبيرة.
- لا تضع كلمة مرور أو مفاتيح API أو بيانات خاصة داخل ملف عام على GitHub.
- البيانات الشخصية ستُحفظ على Google Sheets بعد تفعيل هذه الميزة؛ حدد من له صلاحية الوصول، ومدة الاحتفاظ بالبيانات.
- لا تعِد العميل بإرسال تأكيد بالبريد قبل نجاح الاختبار الفعلي.
- موقع GitHub Pages ثابت (Static) ولا يستطيع بمفرده استقبال طلبات العملاء أو تخزينها.
- يجب تضمين نص سياسة خصوصية مناسب عند تنشيط قاعدة البيانات.
